# RAG-сервис для Ai-DnD

Этот документ описывает архитектуру и использование RAG-сервиса (Retrieval-Augmented Generation) в проекте Ai-DnD.

## Общее описание

RAG-сервис — это микросервис, который:

- Загружает и индексирует официальные PDF-книги D&D 5e из MinIO
- Предоставляет API для семантического поиска по правилам игры
- Интегрируется с n8n для улучшения точности ответов ИИ-ведущего
- Гарантирует, что LLM не галлюцинирует правила, а использует актуальные данные из источников

## Компоненты сервиса

### 1. PDFLoader

Класс для загрузки и обработки PDF:

- Подключается к MinIO по S3 API
- Скачивает PDF-файлы из бакета `dnd-books`
- Извлекает текст с помощью PyPDF2
- Разбивает текст на чанки (512 токенов, оверлап 64)
- Добавляет метаданные (источник, индекс чанка)

### 2. VectorStoreManager

Класс для работы с векторным хранилищем на основе Chroma DB:

- Использует in-memory режим с возможностью сохранения на диск
- Векторизует чанки с помощью модели `paraphrase-multilingual-MiniLM-L12-v2`
- Предоставляет методы для добавления документов и поиска
- Автоматически сохраняет индекс между перезапусками

### 3. FastAPI приложение

REST API с двумя основными эндпоинтами:

#### `GET /`

Проверка работоспособности сервиса.

**Ответ:**
```json
{
  "message": "RAG Service for AI DnD is running"
}
```

#### `GET /health`

Проверка состояния сервиса и векторного хранилища.

**Ответ (успех):**
```json
{
  "status": "healthy",
  "vectorstore_count": 15420,
  "message": "Service is ready to serve requests"
}
```

**Ответ (ошибка):**
```json
{
  "detail": {
    "status": "error",
    "message": "Service is not healthy"
  }
}
```

#### `GET /retrieve`

Семантический поиск по правилам D&D.

**Параметры:**
- `query`: строка поиска (обязательный)
- `top_k`: количество возвращаемых результатов (по умолчанию 3, максимум 10)

**Пример запроса:**
```http
/retrieve?query=как работает заклинание Fireball&top_k=3
```

**Ответ:**
```json
{
  "query": "как работает заклинание Fireball",
  "context": [
    "Заклинание Fireball 3 круга... урон 8к6 огня...",
    "Спасбросок Ловкости для уменьшения урона...",
    "Область действия: 20-футовая сфера..."
  ],
  "sources": [
    "phb.pdf"
  ]
}
```

## Инициализация при старте

При запуске сервис выполняет следующие шаги:

1. Загружает конфигурацию из `config.yaml`
2. Подключается к MinIO
3. Проверяет существование векторного хранилища
4. Если хранилище пустое:
   - Скачивает все PDF из MinIO
   - Извлекает текст
   - Разбивает на чанки
   - Векторизует и индексирует
   - Сохраняет в Chroma DB
5. Если хранилище уже существует — использует его

## Интеграция с n8n

### Обновлённый workflow: "Player Action → AI DM Response"

```plaintext
1. Игрок отправляет действие: "Я кастую Fireball на группу орков"
2. Backend → вызывает n8n workflow
3. n8n:
   a. Запрашивает историю партии из PostgreSQL
   b. Выполняет GET запрос к rag-service с текстом действия
   c. Получает 2–3 релевантных фрагмента правил
   d. Формирует объединённый промпт:
        [System Prompt]
        [Контекст из базы: состояние игры, персонажи, прошлые действия]
        [Контекст из RAG: правила Fireball, урон, спасброски]
        [Текущее действие игрока]
   e. Отправляет в Ollama → получает ответ
   f. Возвращает ответ в Backend
4. Backend сохраняет и отправляет в Frontend
```

## Производительность

| Метрика | Цель | Реализация |
|--------|------|------------|
| Время старта | < 15 сек | Предзагрузка индекса с диска |
| Время поиска | < 300 мс | In-memory Chroma DB, оптимизированные embeddings |
| Память | < 2 GB | Эффективное хранение векторов, очистка временных файлов |
| Задержка сети | Минимальная | Запуск в той же Docker сети |

## Конфигурация

Конфигурация находится в `config.yaml`:

```yaml
books:
  - name: "Player's Handbook"
    file: "phb.pdf"
    sections:
      - "Spells"
      - "Combat"
      - "Classes"
      - "Equipment"
  - name: "Dungeon Master's Guide"
    file: "dmg.pdf"
    sections:
      - "Creating Adventures"
      - "Treasure"
      - "Magic Items"
  - name: "Systems Reference Document"
    file: "srd.pdf"
    sections:
      - "All"

minio:
  bucket: "dnd-books"
  endpoint: "minio:9000"

vectorstore:
  path: "/app/chroma.db"
  collection_name: "dnd_rules"

embedding:
  model: "paraphrase-multilingual-MiniLM-L12-v2"

pdf:
  chunk_size: 512
  chunk_overlap: 64
```

## Docker Compose

Сервис добавлен в `docker-compose.yml`:

```yaml
  rag-service:
    build: 
      context: ../../rag-service
      dockerfile: Dockerfile
    container_name: ai_dnd_rag_service
    ports:
      - "8080:80"
    environment:
      - MINIO_ENDPOINT=minio:9000
      - MINIO_ACCESS_KEY=${MINIO_ROOT_USER}
      - MINIO_SECRET_KEY=${MINIO_ROOT_PASSWORD}
      - MINIO_BUCKET=dnd-books
    volumes:
      - ../../rag-service/chroma.db:/app/chroma.db
    networks:
      - ai_dnd_network
    restart: unless-stopped
    depends_on:
      - minio
```

## Критерии успеха

1. ✅ RAG-сервис стартует за < 15 сек (с предзагрузкой индекса)
2. ✅ Поиск по `Fireball` возвращает правильный фрагмент за < 300 мс
3. ✅ n8n успешно встраивает контекст в промпт Ollama
4. ✅ Ollama использует данные из RAG, а не галлюцинирует правила
5. ✅ Новые PDF можно добавить, просто загрузив в MinIO и перезапустив сервис
