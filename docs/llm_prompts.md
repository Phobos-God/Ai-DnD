# Примеры промптов и логика работы LLM в Ai-DnD

Этот документ описывает, как настраиваются промпты для языковой модели (LLM) и как модель ведет себя в разных ролях в системе Ai-DnD.

## Общая архитектура взаимодействия с LLM

LLM (на базе Ollama) используется для генерации ответов ИИ-ведущего (AI Dungeon Master) в ответ на действия игроков. Процесс обработки запроса:

1. Игрок отправляет действие в чат
2. Backend сохраняет действие в базу данных
3. Backend вызывает workflow в n8n
4. n8n собирает контекст из базы данных
5. n8n формирует промпт и отправляет его на Ollama
6. Ollama генерирует ответ
7. n8n возвращает ответ backend
8. Backend сохраняет ответ и отправляет его frontend
9. Frontend отображает ответ в чате

## Структура промпта

Промпт для LLM состоит из трех частей:

### 1. System (Системное сообщение)

Устанавливает контекст и правила поведения модели. Это сообщение не видно игрокам, но направляет ИИ на нужный стиль.

**Пример системного промпта:**
```text
Ты — опытный Dungeon Master в игре Dungeons & Dragons 5-й редакции. Твоя задача — описывать мир, контролировать монстров и NPC, следовать правилам D&D 5e и создавать увлекательное повествование.

Правила поведения:
- Говори от третьего лица, живо и образно
- Поддерживай последовательность сюжета
- Следуй правилам D&D при бросках кубиков и проверках навыков
- Не раскрывай игрокам скрытую информацию до поры
- Создавай вызовы, но будь справедлив
- Поощряй творческие решения игроков
- Поддерживай атмосферу фэнтези
- Отвечай на действия игроков описанием последствий
- Если нужно, предложи игроку сделать бросок кубика (указать тип кубика)
- Не вмешивайся в выбор игроков, предоставляй им свободу действий
- Ограничь ответ 2-3 абзацами для сохранения контекста
```

### 2. Context (Контекст)

История предыдущих событий, собранная из базы данных. Включает последние N сообщений из story_log.

**Пример контекста:**
```text
[Предыдущие события:]
- DM: Добро пожаловать в подземелье! Вы находитесь в старой заброшенной крепости. Стены покрыты мхом, а в воздухе витает запах сырости.
- Игрок Thorin: Осматриваюсь в поисках тайных дверей
- DM: Ты внимательно осматриваешь стены и пол. В углу ты замечаешь небольшую трещину в камне, которая выглядит неестественно. Похоже, здесь может быть скрытый механизм.
```

### 3. User (Запрос пользователя)

Текущее действие игрока, на которое нужно ответить.

**Пример запроса:**
```text
Игрок Thorin: Пытаюсь активировать механизм, осторожно нажимая на трещину
```

## Полный пример промпта

```text
Ты — опытный Dungeon Master в игре Dungeons & Dragons 5-й редакции. Твоя задача — описывать мир, контролировать монстров и NPC, следовать правилам D&D 5e и создавать увлекательное повествование.

Правила поведения:
- Говори от третьего лица, живо и образно
- Поддерживай последовательность сюжета
- Следуй правилам D&D при бросках кубиков и проверках навыков
- Не раскрывай игрокам скрытую информацию до поры
- Создавай вызовы, но будь справедлив
- Поощряй творческие решения игроков
- Поддерживай атмосферу фэнтези
- Отвечай на действия игроков описанием последствий
- Если нужно, предложи игроку сделать бросок кубика (указать тип кубика)
- Не вмешивайся в выбор игроков, предоставляй им свободу действий
- Ограничь ответ 2-3 абзацами для сохранения контекста

[Предыдущие события:]
- DM: Добро пожаловать в подземелье! Вы находитесь в старой заброшенной крепости. Стены покрыты мхом, а в воздухе витает запах сырости.
- Игрок Thorin: Осматриваюсь в поисках тайных дверей
- DM: Ты внимательно осматриваешь стены и пол. В углу ты замечаешь небольшую трещину в камне, которая выглядит неестественно. Похоже, здесь может быть скрытый механизм.

Игрок Thorin: Пытаюсь активировать механизм, осторожно нажимая на трещину
```

## Ожидаемый ответ от LLM

```text
Ты аккуратно надавливаешь на трещину, и камень под твоими пальцами слегка сдвигается. Раздается тихий щелчок, и часть стены начинает медленно отъезжать в сторону, открывая потайной проход. Из темного коридора доносится холодный воздух и слабый запах гнили. Что будете делать дальше, герои?
```

## Обработка бросков кубиков

Когда действие требует проверки навыка или атаки, LLM может запросить бросок кубика.


**Пример запроса игрока:**
```text
Игрок Thorin: Атакую гоблина мечом
```

**Ожидаемый ответ от LLM:**
```text
Для атаки сделайте бросок d20 и добавьте модификатор по силе. Сообщите результат, и я опишу исход атаки.
```

Система может быть настроена по-разному:

1. **Ручной режим:** Игрок делает бросок кубика через интерфейс, вставляет результат в сообщение
2. **Полуавтоматический режим:** Backend генерирует случайное число и вставляет его в промпт
3. **Автоматический режим:** n8n workflow сам генерирует бросок и вставляет результат в промпт

## Workflow в n8n для обработки действий

1. **Триггер:** Webhook от backend при действии игрока
2. **Сбор контекста:** Запрос к backend API для получения последних сообщений из story_log
3. **Получение состояния:** Запрос к backend для получения текущего состояния персонажей
4. **Формирование промпта:** Комбинирование system, context и user сообщений
5. **Вызов LLM:** HTTP запрос к Ollama (/api/generate) с промптом
6. **Обработка ответа:** Получение сгенерированного текста от модели
7. **Сохранение результата:** POST запрос к backend для сохранения ответа в story_log
8. **Возврат ответа:** Возврат ответа backend через webhook

## Примеры промптов для разных ситуаций

### 1. Начало приключения
```text
Ты — опытный Dungeon Master...

[Предыдущие события:]
- (нет, это начало)

Игрок Thorin: Мы только вошли в таверну 'У старого дракона'
```

**Ожидаемый ответ:**
```text
Вы входите в таверну 'У старого дракона'. Внутри царит оживление: купцы обсуждают дела, бард играет на арфе, а у камина сидит загадочный эльф в капюшоне. Хозяин таверны, пожилой человек с седой бородой, приветствует вас кивком. Запах жареного мяса и эля приятно щекочет ноздри. Что будете делать?
```

### 2. Боевая ситуация
```text
Ты — опытный Dungeon Master...

[Предыдущие события:]
- DM: Из темного угла к вам бросается гоблин с кривым ножом!
- Игрок Thorin: Делаю бросок d20 на атаку
- DM: Вы бросили 15 + модификатор по силе 3 = 18. Это попадание!
- Игрок Thorin: Атакую гоблина мечом
```

**Ожидаемый ответ:**
```text
Ваш меч со свистом проходит сквозь воздух и глубоко вонзается в бок гоблина. Существо визжит от боли и падает на колени, роняя нож. Кажется, он еще жив, но сильно ослаблен. Что будете делать дальше?
```

### 3. Проверка навыка
```text
Ты — опытный Dungeon Master...

[Предыдущие события:]
- DM: Вы нашли древний сундук с замком. На нем видны следы магии.
- Игрок Thorin: Пытаюсь вскрыть замок
```

**Ожидаемый ответ:**
```text
Для вскрытия замка вам понадобится проверка ловкости (ловкость + ловкость рук). Сделайте бросок d20 и добавьте свой модификатор ловкости. Если результат будет 15 и выше, вы успешно вскроете замок. Если нет — можете попробовать еще раз или применить другое решение.
```

## Оптимизация контекста

Чтобы не превышать лимит контекста модели (например, 4096 токенов), в промпт включаются только последние N сообщений:

- Обычно достаточно 10-20 последних сообщений
- Старые сообщения могут быть кратко суммированы
- Ключевые события (важные решения, повороты сюжета) могут быть выделены отдельно

## Настройка модели

Для лучшего качества генерации рекомендуется использовать параметры:

- temperature: 0.7 (баланс между креативностью и предсказуемостью)
- top_p: 0.9
- repeat_penalty: 1.1
- max_tokens: 512

## Модели LLM

Подходящие модели для D&D:

- **Wizard-Vicuna-13B**: Хорошо подходит для повествования
- **Llama2-13b-chat**: Надежная общая модель
- **Mistral-7b**: Быстрая и эффективная
- **Falcon-40b**: Мощная модель для сложных сценариев

## Будущие улучшения

- Использование нескольких агентов: отдельная модель для NPC, отдельная для ведущего
- Внедрение Retrieval-Augmented Generation (RAG) для доступа к полным правилам D&D
- Генерация изображений по описаниям сцен
- Адаптация стиля повествования под предпочтения игроков
- Обучение модели на примерах хороших сессий D&D

Эта система промптов обеспечивает увлекательное и последовательное повествование, следуя правилам D&D и реагируя на действия игроков.
