# 📋 Инструкция по запуску и настройке Ai-DnD

Этот документ содержит пошаговую инструкцию по запуску и настройке проекта Ai-DnD. После выполнения всех шагов вы сможете запустить локального ИИ-ведущего для D&D 5e с поддержкой RAG.

## 🛠️ Предварительные требования

Перед началом убедитесь, что у вас установлено:

- **Docker** и **Docker Compose** (рекомендуется последняя версия)
- **Git** (для клонирования репозитория)
- Достаточно ресурсов:
  - Минимум **16 ГБ RAM** (рекомендуется 32 ГБ+)
  - **50+ ГБ свободного места** на диске (для моделей LLM и PDF-книг)
  - **GPU с поддержкой CUDA** (рекомендуется для быстрой работы Ollama)

## 📂 Структура проекта

После клонирования репозитория у вас должна быть следующая структура:

```
Ai-DnD/
├── backend/            # FastAPI приложение
├── frontend/           # React интерфейс
├── infrastructure/     # Docker Compose и конфигурация
├── rag-service/        # RAG-сервис для поиска по правилам
├── docs/               # Документация
├── .env.example        # Пример переменных окружения
├── .env                # Ваши переменные окружения
├── README.md           # Основная документация
└── docker-compose.yml  # Конфигурация Docker
```

## 🚀 Пошаговая инструкция по запуску

### Шаг 1: Настройка переменных окружения

1. Скопируйте файл `.env.example` в `.env`:
```bash
Copy-Item .env.example .env
```

2. Откройте файл `.env` и при необходимости измените значения переменных. Основные переменные:
```env
# Пароли для баз данных и сервисов
POSTGRES_PASSWORD=ai_dnd_pass
MINIO_ROOT_PASSWORD=minioadmin

# Порты (если стандартные заняты)
BACKEND_PORT=8000
FRONTEND_PORT=3000
N8N_PORT=5678
```

### Шаг 2: Подготовка PDF-книг D&D 5e

RAG-сервис требует PDF-файлы официальных книг D&D 5e. Их нужно поместить в директорию `minio_data/dnd-books/`.

1. Создайте директорию для книг:
```bash
New-Item -ItemType Directory -Path "minio_data/dnd-books"
```

2. Поместите в неё следующие PDF-файлы:
   - `phb.pdf` - Player's Handbook
   - `dmg.pdf` - Dungeon Master's Guide
   - `srd.pdf` - Systems Reference Document

> ⚠️ Внимание: В этом демо-запуске создаются пустые файлы для проверки структуры. В реальной системе вы должны поместить туда настоящие PDF-файлы с текстовым слоем (не сканы).

### Шаг 3: Запуск контейнеров

1. Запустите все сервисы с помощью Docker Compose:
```bash
docker-compose -f infrastructure/docker/docker-compose.yml down
docker builder prune -f
docker-compose -f infrastructure/docker/docker-compose.yml build --no-cache
docker-compose -f infrastructure/docker/docker-compose.yml up -d
```

2. Проверьте статус сервисов:
```bash
docker-compose -f infrastructure/docker/docker-compose.yml ps
```

Вы должны увидеть все сервисы в статусе `Up`.

### Шаг 4: Проверка работы RAG-сервиса

1. Проверьте, что RAG-сервис запущен:
```bash
Invoke-RestMethod -Uri http://localhost:8080/health
```

Ожидаемый ответ:
```json
{
  "status": "healthy",
  "vectorstore_count": 0,
  "message": "Service is ready to serve requests"
}
```

2. При первом запуске RAG-сервис автоматически:
   - Подключится к MinIO
   - Загрузит PDF-файлы
   - Извлечет текст
   - Создаст векторный индекс
   - Сохранит его в `rag-service/chroma.db`

> ⏱️ Процесс индексации может занять несколько минут в зависимости от размера PDF.

### Шаг 5: Настройка Ollama и загрузка модели

Ollama не поставляется с предустановленной моделью. Вам нужно загрузить подходящую модель вручную.

1. Подключитесь к контейнеру Ollama:
```bash
docker exec -it ai_dnd_ollama sh
```

2. Загрузите модель (рекомендуется одна из следующих):

**Для CPU (умеренное качество):**
```bash
ollama pull llama2:7b
```

**Для GPU (хорошее качество):**
```bash
ollama pull llama2:13b
```

**Для продвинутых сценариев (лучшее качество):**
```bash
ollama pull wizard-vicuna-13b
```

3. Проверьте доступные модели:
```bash
ollama list
```

### Шаг 6: Настройка n8n workflow

1. Откройте веб-интерфейс n8n: [http://localhost:5678](http://localhost:5678)

2. Создайте новый workflow для обработки действий игроков:

   - **Webhook Node**: для получения действий от backend
   - **HTTP Request Node**: для запроса истории партии из backend
   - **HTTP Request Node**: для запроса правил из rag-service (`http://rag-service:80/retrieve?query={{ $json["action"] }}`)
   - **LLM Node**: для вызова Ollama с объединённым промптом
   - **HTTP Request Node**: для отправки ответа в backend

3. Убедитесь, что в LLM Node указана правильная модель (например, `llama2:13b`)

### Шаг 7: Запуск фронтенда

1. Откройте веб-интерфейс: [http://localhost:3000](http://localhost:3000)

2. Создайте новую партию или подключитесь к существующей

3. Создайте персонажа и начните игру

### 2. Модель для Ollama

Модель **не загружается автоматически**. Вы должны загрузить её вручную через команду `ollama pull` после запуска контейнера.

Рекомендуемые модели:

| Модель | Требования | Качество |
|--------|------------|---------|
| `llama2:7b` | 8 ГБ RAM | Удовлетворительное |
| `llama2:13b` | 16 ГБ RAM + GPU | Хорошее |
| `wizard-vicuna-13b` | 16 ГБ RAM + GPU | Отличное |
| `mistral:7b` | 8 ГБ RAM | Очень хорошее |

### 3. Конфигурация MinIO

1. Откройте веб-консоль MinIO: [http://localhost:9001](http://localhost:9001)

2. Войдите с логином и паролем из `.env` (`minioadmin`/`minioadmin`)

3. Убедитесь, что бакет `dnd-books` создан автоматически или создайте его вручную

4. При необходимости добавьте другие бакеты:
   - `maps` - для карт
   - `avatars` - для аватаров персонажей

## 🔄 Процесс первого запуска

При первом запуске система выполнит следующие действия:

1. Docker Compose запустит все сервисы
2. RAG-сервис:
   - Подключится к MinIO
   - Проверит наличие PDF-файлов в бакете `dnd-books`
   - Загрузит их
   - Создаст векторный индекс
   - Сохранит индекс в `rag-service/chroma.db`
3. При последующих запусках индекс будет загружаться из `chroma.db`, что значительно ускорит старт

## 🔄 Обновление системы

### Добавление новых книг

1. Поместите новый PDF-файл в `minio_data/dnd-books/`
2. Перезапустите RAG-сервис:
```bash
docker-compose -f infrastructure/docker/docker-compose.yml restart rag-service
```
3. Сервис автоматически проиндексирует новый файл

### Обновление модели Ollama

1. Загрузите новую модель:
```bash
docker exec -it ai_dnd_ollama ollama pull новая_модель
```
2. Обновите workflow в n8n, указав новое имя модели

## 🚨 Возможные проблемы и решения

| Проблема | Решение |
|---------|--------|
| `rag-service` не может подключиться к MinIO | Убедитесь, что `minio_data` существует и права доступа корректны |
| Ошибка при индексации PDF | Проверьте, что PDF имеет текстовый слой (не скан) |
| Ollama не отвечает | Проверьте, загружена ли модель командой `ollama list` |
| n8n не может вызвать rag-service | Убедитесь, что сервисы в одной сети и rag-service запущен |
| Медленный ответ LLM | Убедитесь, что используется GPU и выбрана подходящая модель |
