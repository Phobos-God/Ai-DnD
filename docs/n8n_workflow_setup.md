# 🛠️ Подробная инструкция по настройке workflow в n8n для Ai-DnD

Этот документ содержит максимально подробное описание конфигурации workflow в n8n для корректной работы системы Ai-DnD. Данный workflow отвечает за обработку действий игроков и генерацию ответов ИИ-ведущего с использованием RAG-сервиса и LLM.

## 🎯 Назначение workflow

Workflow предназначен для обработки игровых действий игроков и генерации контекстуально точных ответов ИИ-ведущего. Он интегрирует несколько сервисов:

- **Backend (FastAPI)**: для получения контекста игры
- **RAG-сервис**: для извлечения релевантных правил D&D 5e
- **Ollama**: для генерации текста с помощью LLM
- **Backend (FastAPI)**: для сохранения и передачи ответа игрокам

## 🗺️ Общая схема workflow

```plaintext
+----------------+     +---------------------+     +---------------------+
|                |     |                     |     |                     |
|   Webhook      |---->|  Получение контекста |---->|  Запрос к RAG-сервису |
|   (Действие    |     |  игры (история,     |     |  (правила D&D)       |
|   игрока)      |     |  персонажи)         |     |                     |
|                |     |                     |     |                     |
+----------------+     +---------------------+     +---------------------+
                                                                      |
                                                                      v
+---------------------+     +---------------------+     +---------------------+
|                     |     |                     |     |                     |
|  Формирование       |<----|  Объединение        |<----|  Обработка          |
|  промпта            |     |  контекста          |     |  ответа RAG-сервиса |
|                     |     |                     |     |                     |
+---------------------+     +---------------------+     +---------------------+
                                                                      |
                                                                      v
+---------------------+     +---------------------+     +---------------------+
|                     |     |                     |     |                     |
|  Вызов Ollama       |---->|  Обработка          |---->|  Отправка ответа    |
|  (генерация ответа) |     |  ответа LLM         |     |  в Backend          |
|                     |     |                     |     |                     |
+---------------------+     +---------------------+     +---------------------+
```

## 🧩 Пошаговая настройка узлов (nodes)

### 1. Webhook Node: Прием действия игрока

**Тип узла**: Webhook

**Настройки**:
- **Name**: `Webhook: Player Action`
- **HTTP Method**: `POST`
- **Path**: `/workflow/player-action`
- **Response Code**: `200`
- **Response Mode**: `Last Node`
- **Response Data**: `Response`

**Описание**:
Этот узел служит точкой входа для действий игроков. Backend (FastAPI) отправляет сюда POST-запрос при каждом действии игрока в чате.

**Ожидаемый входной JSON**:
```json
{
  "action": "Игрок исследует комнату",
  "player_id": "123",
  "session_id": "abc",
  "character_name": "Гром Молотов"
}
```

**Совет**: Убедитесь, что узел настроен на ожидание JSON-данных и правильно обрабатывает CORS, если frontend и n8n находятся на разных доменах.

### 2. HTTP Request Node: Получение истории партии

**Тип узла**: HTTP Request

**Настройки**:
- **Name**: `GET Session History`
- **Request Method**: `GET`
- **URL**: `http://backend:8000/api/story_log?limit=30`
- **Response Format**: `JSON`

**Описание**:
Этот узел запрашивает у backend'а полную историю игровой сессии, включая все предыдущие действия игроков и ответы ведущего.

**Используемые переменные**:
- `{{ $json["session_id"] }}` — ID игровой сессии из входного вебхука

**Ожидаемый ответ от backend**:
```json
[
  {
    "type": "player",
    "content": "Привет, я вхожу в пещеру",
    "timestamp": "2025-12-21T10:00:00Z"
  },
  {
    "type": "dm",
    "content": "Вы входите в темную пещеру с капающей водой со свода",
    "timestamp": "2025-12-21T10:01:00Z"
  }
]
```

### 3. HTTP Request Node: Получение состояния персонажей

**Тип узла**: HTTP Request

**Настройки**:
- **Name**: `GET Character State`
- **Request Method**: `GET`
- **URL**: `http://backend:8000/api/characters`
- **Response Format**: `JSON`

**Описание**:
Этот узел получает текущее состояние всех персонажей в сессии, включая их характеристики, инвентарь, здоровье и уровень.

**Ожидаемый ответ от backend**:
```json
[
  {
    "name": "Гром Молотов",
    "class": "Воин",
    "level": 3,
    "hp": 25,
    "max_hp": 25,
    "inventory": ["Меч", "Щит"],
    "abilities": {"Сила": 16, "Ловкость": 12}
  }
]
```

### 4. HTTP Request Node: Запрос к RAG-сервису

**Тип узла**: HTTP Request

**Настройки**:
- **Name**: `RAG: Retrieve Rules`
- **Request Method**: `GET`
- **URL**: `http://rag-service:8080/retrieve?query={{ $json["action"] }}`
- **Response Format**: `JSON`
- **Timeout**: `30000` (30 секунд)

**Описание**:
Этот узел отправляет текст действия игрока в RAG-сервис для поиска релевантных правил D&D 5e. RAG-сервис возвращает до 3 наиболее релевантных фрагментов из PDF-книг (PHB, DMG, SRD).

**Используемые переменные**:
- `{{ $json["action"] }}` — текст действия игрока из вебхука

**Ожидаемый ответ от RAG-сервиса**:
```json
{
  "query": "исследует комнату",
  "results": [
    {
      "content": "При исследовании помещения персонажи могут сделать проверку Мудрости (Внимание) чтобы заметить скрытые детали...",
      "metadata": {
        "source": "phb.pdf",
        "page": 178
      },
      "score": 0.85
    }
  ]
}
```

### 5. Function Node: Объединение контекста

**Тип узла**: Function

**Настройки**:
- **Name**: `Combine Context`
- **JavaScript Code**:

```javascript
// Получаем данные из предыдущих узлов
const storyLog = $input.all()[1].json; // История из story_log
const characters = $input.all()[2].json; // Состояние персонажей
const ragResults = $input.all()[3].json; // Результаты RAG
const playerAction = $json.action; // Действие игрока
const characterName = $json.character_name; // Имя персонажа

// Формируем контекст
const context = {
  history: storyLog.map(item => `[${item.timestamp}] ${item.character_id ? 'Player' : 'DM'}: ${item.content}`).join('\n'),
  characters: characters,
  rag_rules: ragResults.results.map(r => `Источник: ${r.metadata.source}, стр. ${r.metadata.page}\n${r.content}`).join('\n\n'),
  current_action: playerAction,
  current_character: characterName
};

return [context];
```

**Описание**:
Этот узел объединяет все полученные данные в единый контекстный объект, который будет использован для формирования промпта. Узел обрабатывает выходные данные всех предыдущих HTTP-запросов и структурирует их для последующего использования.

### 6. Function Node: Формирование промпта

**Тип узла**: Function

**Настройки**:
- **Name**: `Format LLM Prompt`
- **JavaScript Code**:

```javascript
// Получаем объединенный контекст
const context = $input.all()[0].json;

// Системный промпт для ИИ-ведущего
const systemPrompt = `Ты — опытный ведущий (Dungeon Master) для Dungeons & Dragons 5e. Твоя задача — управлять игровой сессией, описывать мир, контролировать монстров и NPC, а также точно следовать правилам игры.

## Требования:
1. Отвечай от лица ведущего в повествовательной форме
2. Используй правила из RAG-сервиса при необходимости
3. Сохраняй игровой баланс и логику мира
4. Будь креативным, но последовательным
5. Учитывай состояние персонажей и историю сессии

## Контекст игры:
- Текущее действие: ${context.current_action}
- Персонаж, совершающий действие: ${context.current_character}

## История сессии:
${context.history}

## Состояние персонажей:
${context.characters.map(c => `- ${c.name} (${c.class} ${c.level}): ${c.hp}/${c.max_hp} HP, Инвентарь: ${c.inventory.join(', ')}`).join('\n')}

## Релевантные правила из D&D 5e:
${context.rag_rules}

## Инструкция:
На основе всего вышеперечисленного сгенерируй ответ на действие игрока. Опиши, что происходит в мире, какие проверки нужно сделать (если необходимо), и какие последствия может иметь это действие.`;

// Формируем финальный промпт
const finalPrompt = {
  model: "qwen3:4b-instruct", // актуальная легковесная модель
  prompt: systemPrompt,
  stream: false,
  temperature: 0.7,
  max_tokens: 512
};

return [finalPrompt];
```

**Описание**:
Этот узел формирует финальный промпт для LLM, объединяя системные инструкции, контекст игры, историю сессии, состояние персонажей и релевантные правила из RAG-сервиса. Промпт спроектирован так, чтобы ИИ-ведущий генерировал точные, контекстуально релевантные и соответствующие правилам ответы.

### 7. HTTP Request Node: Вызов Ollama (LLM)

**Тип узла**: HTTP Request

**Настройки**:
- **Name**: `LLM: Generate Response`
- **Request Method**: `POST`
- **URL**: `http://ollama:11434/api/generate`
- **Content-Type**: `Application JSON`
- **Body**: `{{ $json | json }}` (автоматически подставляет выход из Function Node)
- **Response Format**: `JSON`
- **Timeout**: `60000` (60 секунд)

**Описание**:
Этот узел отправляет сформированный промпт в Ollama для генерации текста с помощью LLM. Ollama возвращает сгенерированный ответ в виде потока токенов или полного сообщения.

**Ожидаемый запрос к Ollama**:
```json
{
  "model": "qwen3:4b-instruct",
  "prompt": "Ты — опытный ведущий...",
  "stream": false,
  "temperature": 0.7,
  "max_tokens": 512
}
```

**Ожидаемый ответ от Ollama**:
```json
{
  "model": "qwen3:4b-instruct",
  "response": "Гром Молотов, вы осторожно входите в темную комнату. Стены покрыты влажным мхом, а на полу видны следы...",
  "done": true
}
```

### 8. Function Node: Обработка ответа LLM

**Тип узла**: Function

**Настройки**:
- **Name**: `Process LLM Response`
- **JavaScript Code**:

```javascript
// Получаем ответ от LLM
const llmResponse = $input.all()[0].json;

// Извлекаем текст ответа
const responseText = llmResponse.response.trim();

// Формируем объект для отправки в backend
const dmResponse = {
  "type": "dm",
  "content": responseText,
  "timestamp": new Date().toISOString(),
  "source": "ai_dm",
  "metadata": {
    "model": llmResponse.model,
    "tokens": llmResponse.eval_count || 0
  }
};

return [dmResponse];
```

**Описание**:
Этот узел обрабатывает сырой ответ от LLM, извлекает текст и форматирует его в структуру, ожидаемую backend'ом для сохранения в истории сессии.

### 9. HTTP Request Node: Отправка ответа в Backend

**Тип узла**: HTTP Request

**Настройки**:
- **Name**: `POST DM Response`
- **Request Method**: `POST`
- **URL**: `http://backend:8000/api/story_log`
- **Content-Type**: `Application JSON`
- **Body**: `{{ $json | json }}` (автоматически подставляет обработанный ответ)
- **Response Format**: `JSON`

**Описание**:
Этот узел отправляет сгенерированный ответ ИИ-ведущего обратно в backend, где он сохраняется в истории сессии и транслируется всем игрокам через WebSocket.

**Ожидаемый запрос к backend**:
```json
{
  "type": "dm",
  "content": "Гром Молотов, вы осторожно входите в темную комнату...",
  "timestamp": "2025-12-21T10:02:00Z",
  "source": "ai_dm",
  "metadata": {
    "model": "qwen3:4b-instruct",
    "tokens": 156
  }
}
```

## ⚙️ Дополнительные настройки workflow

### Ошибки и обработка исключений

Рекомендуется добавить обработку ошибок:

1. **Error Trigger Node**: для перехвата ошибок в workflow
2. **Function Node**: для формирования сообщения об ошибке
3. **HTTP Request Node**: для отправки уведомления об ошибке в backend

### Логирование

- Добавьте **Debug Node** после каждого ключевого узла для отладки
- Используйте **Set Node** для сохранения промежуточных данных в переменные workflow

### Переменные окружения

Рекомендуется использовать переменные окружения для:
- URL сервисов (`BACKEND_URL`, `RAG_SERVICE_URL`, `OLLAMA_URL`)
- Таймаутов
- Параметров LLM (температура, max_tokens)

## 🔐 Безопасность

1. **Аутентификация**: Убедитесь, что n8n защищен паролем или API-ключом
2. **Валидация входных данных**: Добавьте проверку входного JSON на наличие обязательных полей
3. **Ограничение скорости**: Настройте rate limiting для вебхука
4. **Шифрование**: Убедитесь, что все HTTP-запросы между сервисами происходят по внутренней Docker-сети
