# Архитектура Ai-DnD

Этот документ описывает архитектурную схему проекта Ai-DnD — автоматизированного ведущего для D&D 5e на базе LLM.

## Общая архитектура

```plaintext
+----------------+     +----------------+     +-------------------+
|                |     |                |     |                   |
|   Frontend     |<--->|   Backend      |<--->|   PostgreSQL      |
|   (React)      | HTTP |   (FastAPI)    | ORM  |   (База данных)   |
|                |     |                |     |                   |
+----------------+     +----------------+     +-------------------+
       |                       |
       |                       |      +-----------------+
       |                       |<---->|   MinIO         |
       |                       | HTTP |   (Хранилище)   |
       |                       |      +-----------------+
       |                       |
       |                       |      +-----------------+
       |                       |<---->|   Ollama        |
       |                       | HTTP |   (LLM Server)  |
       |                       |      +-----------------+
       |                       |
       |                       |      +-----------------+
       |                       |<---->|   n8n           |
       |                       | HTTP |   (Оркестратор) |
       |                       |      +-----------------+
       |                       |
       |                       |      +-----------------+
       |                       |<---->|   rag-service   |
       |                       | HTTP |   (RAG)         |
       |                       |      +-----------------+
       |                       |
       +-----------------------+       (Docker Compose)

```

## Компоненты системы

### 1. Frontend (React)

Веб-интерфейс для игроков, построенный на React. Предоставляет:

- Экран подключения к партии
- Генератор и редактор персонажей
- Чат с ИИ-ведущим
- Отображение карты с токенами
- Лист персонажа с характеристиками

Взаимодействует с Backend через REST API и WebSocket.

### 2. Backend (FastAPI)

Серверная часть на FastAPI (Python), предоставляющая REST API для всех функций приложения:

- Аутентификация игроков
- Управление персонажами (CRUD)
- Логирование событий партии
- Взаимодействие с LLM через n8n
- Интеграция с MinIO для хранения файлов
- Реализация бизнес-логики D&D (броски кубиков, проверки правил)

### 3. Database (PostgreSQL)

Реляционная база данных для хранения всех данных игры:

- Партии и игроки
- Персонажи и их состояние
- История действий и повествования
- Инвентарь, уровень, броски кубиков

Используется SQLAlchemy ORM для взаимодействия.

### 4. MinIO (объектное хранилище)

S3-совместимое хранилище для файлов:

- Изображения карт
- Аватары персонажей
- Иллюстрации к событиям
- Другие медиафайлы

Backend сохраняет и извлекает файлы через MinIO API.

### 5. Ollama (LLM Server)

Локальный сервер для запуска и управления языковыми моделями:

- Обеспечивает API для генерации текста
- Поддерживает различные модели (Llama2, Wizard-Vicuna и др.)
- Работает с GPU/CPU
- Доступен по HTTP API

### 6. n8n (Оркестратор workflow)

Платформа автоматизации для оркестрации сложных процессов:

- Workflow 1: Обработка действия игрока → генерация ответа ИИ-ведущего (с интеграцией RAG-сервиса)
- Workflow 2: Подсчет опыта и повышение уровня персонажей
- Интеграция между Backend, LLM, RAG-сервисом и другими сервисами

## Docker Compose инфраструктура

Система разворачивается локально с помощью Docker Compose, включающего сервисы:

- `db`: PostgreSQL для хранения данных
- `minio`: MinIO для объектного хранилища (хранение PDF книг и медиа)
- `ollama`: Ollama для запуска LLM
- `n8n`: n8n для оркестрации workflow
- `backend`: FastAPI приложение
- `frontend`: React интерфейс
- `rag-service`: RAG-сервис для семантического поиска по правилам D&D

Все сервисы соединены в одной Docker сети и обмениваются данными через внутренние хостнеймы.

## Основные workflow

### 1. Действие игрока → ответ AI DM

1. Игрок отправляет действие в чат
2. Frontend → Backend (HTTP POST)
3. Backend сохраняет действие и вызывает n8n workflow
4. n8n собирает контекст из БД
5. n8n выполняет запрос к rag-service для получения релевантных правил D&D
6. n8n формирует объединённый prompt (контекст игры + правила из RAG) и вызывает Ollama
7. Ollama генерирует ответ
8. n8n возвращает ответ Backend
9. Backend сохраняет ответ и отправляет Frontend
10. Frontend отображает ответ в чате

### 2. Завершение боя → начисление XP

1. Игрок или ИИ отмечает окончание боя
2. Backend вызывает n8n workflow
3. n8n рассчитывает опыт за побежденных врагов
4. n8n распределяет опыт между выжившими персонажами
5. n8n обновляет уровень персонажей в БД
6. Backend уведомляет игроков о повышении уровня
7. Игроки выбирают улучшения через интерфейс

## Безопасность

- Все сервисы изолированы в Docker
- Переменные окружения хранятся в .env файле
- n8n защищен аутентификацией
- MinIO использует учетные данные
- Backend проверяет права доступа к ресурсам

## Масштабируемость

- Frontend и Backend могут быть масштабированы независимо
- База данных поддерживает репликацию
- LLM может быть заменен на более производительный
- n8n позволяет добавлять новые workflow без изменения кода backend

Эта архитектура обеспечивает гибкость, надежность и простоту развертывания локального AI Dungeon Master для D&D.
